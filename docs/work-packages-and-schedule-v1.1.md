## 1. 各工作包详解

### 包 1 · 曾子煜：账号与接口规范

**工作内容**：登录注册、密码、权限、接口规范。

- **后端**：工程脚手架（Monorepo、`docker-compose` PG16+Redis7、Flyway V1 基线）、`common/` 统一响应/异常/错误码/traceId/分页、Spring Security 6 + JWT 双 Token + Redis 黑名单、注册/登录/刷新/登出/改密/`me`、5 表 RBAC + `@PreAuthorize`、游客白名单、Knife4j、后台用户管理接口（查询/封禁/删除，封禁联动踢下线）。
- **前端**：用户端登录注册弹窗、修改密码页。
- **接口规范**：`docs/api-conventions.md`（路由前缀、统一响应体、错误码号段、Token 约定、分页结构），作为全组联调唯一依据。
- **验收**：新人 `pnpm i` + `docker compose up` + 启动后端即可登录并在 Knife4j 调通；越权返 403；封禁后旧 Token 立即失效。
- **依赖**：无（自身即地基，D3 前必须可用）。

### 包 2 · 李悦凯：发布与视频处理

**工作内容**：图文视频上传、标签、编辑删除、视频处理。

- **后端**：`StorageAdapter`（Local / S3）、上传接口与文件校验、`media_assets` 表、作品 CRUD（TEXT / IMAGE / VIDEO 三形态）、标签 CRUD 与关联、编辑/逻辑删除、三档可见性、FFmpeg 异步抽首帧 + ffprobe + HLS 切片 + HTTP Range 降级。
- **前端**：发布页（三形态切换、九宫格上传、标签选择、可见性选择）、编辑页、`VideoPlayer`（hls.js + 封面 + 失败降级）。
- **验收**：图文/视频/纯文三种形态都能发；9 图上传正常；传 mp4 出封面并播 HLS，无 FFmpeg 环境自动走 Range；编辑与删除生效且只作用于本人作品。
- **依赖**：包 1（鉴权与 common）。
- **备注**：本包含视频流加分项，工作量偏重，视频处理允许降级验收（Range 兜底可用即算通过），HLS 作为满分项。

### 包 3 · 韩瑞凯：浏览与检索

**工作内容**：首页瀑布流、详情页、搜索、我的作品。

- **后端**：瀑布流分页（可选 cursor）、详情聚合（作品 + 媒体 + 作者 + 我的互动状态 + 评分）、检索（关键词 `pg_trgm`、标签、日期区间、内容类型、最新/最热/最高分排序）、我的作品列表。
- **前端**：响应式导航框架、`WaterfallGrid` / `PostCard`、详情页（弹窗或独立页）、搜索页与筛选排序、我的作品列表页。
- **验收**：首页双列/多列自适应；组合筛选与排序结果正确；详情页点赞态、关注态、评分态齐全；我的作品按时间倒序且可进入编辑。
- **依赖**：包 1、包 2（作品与媒体数据）、包 4/5（互动状态字段）、包 7（排序服务）。

### 包 4 · 张锦泽：互动与评价

**工作内容**：点赞、收藏、评论回复、评分。

- **后端**：点赞/收藏（联合唯一索引 + 计数一致性）、两级平铺评论与回复分页（`root_id` / `parent_id` / `reply_to_user_id`）、1~5 星评分（唯一约束、可改分、作者不可自评、均分与人数冗余更新）。
- **前端**：点赞收藏按钮、`CommentDrawer`（含展开更多回复）、`RatingBox`、我的收藏页。
- **验收**：重复点赞不重复计数；同一用户改分不新增记录；详情页显示「4.8 分（23 人评）」。
- **依赖**：包 1、包 2。

### 包 5 · 叶立铭：社交与好友圈

**工作内容**：关注互关、个人主页、粉丝列表、关注流。

- **后端**：关注/取关、互关 `is_mutual` 维护、粉丝/关注列表、关注流、个人主页聚合数据、好友可见作品过滤。
- **前端**：个人主页（从头像进入）、关注/粉丝列表、关注流 tab、关注按钮。
- **验收**：互关后能看到对方 FRIENDS 作品，取消关注立即不可见；粉丝与关注列表数量一致。
- **依赖**：包 1、包 2（可见性字段）、包 3（主页展示组件可复用）。

### 包 6 · 周家琦：后台管理

**工作内容**：用户、内容、评论、标签管理。

- **前端**：管理后台框架（布局 / 路由守卫 / 菜单 / 按钮权限指令 / 登录页）、用户管理页（查询/封禁/删除）、内容管理页（筛选/下架/删除）、评论管理页（查询/删除）、标签管理页（增删改查）。
- **后端**：后台聚合管理接口（内容、评论、标签的查询与操作）；用户管理接口由包 1 提供，本包负责对接。
- **验收**：管理员登录后四类管理页可用；下架/删除后用户端立即不可见；无权限角色看不到对应菜单与按钮。
- **依赖**：包 1（认证与权限点、用户管理接口）、包 2（内容接口）、包 4（评论接口）。

### 包 7 · 李希宇：加分项

**工作内容**：敏感词、大模型、推荐排序、统计图。

- **敏感词**：DFA 前缀树（内存热更新 + Redis 版本号）、词库 CRUD、高危词拦截与一般不文明词打码策略、后台敏感词库页。
- **大模型**：OpenAI 兼容客户端 + Redis 限流 + 降级业务码、三个场景（发布页 AI 打标/润色、详情页内容与评论总结、异步合规语义复查）、`audit_records` 留痕、后台待复审队列页。
- **推荐排序**：热度分 + 标签匹配的排序服务，供首页流调用（可用「最新/最热/最高分」三档呈现）。
- **统计图**：统计查询接口 + 后台 ECharts 看板（指标卡、注册/发帖趋势、标签分布、内容类型占比、排行榜）。
- **验收**：高危词发布被拦并提示命中词；AI 不可用时发帖浏览主流程不受影响；首页热榜随互动变化；看板数据与库内一致。
- **依赖**：包 1、包 2、包 4（审核需评论数据）、包 6（后台框架容器）。

### 包 8 · 陈建辉：测试、部署与交付保障

**工作内容**：测试、部署、种子数据、四个附件、报告统稿、PPT。

- **测试**：测试计划与用例（每包出一份，本包汇总）、冒烟与回归测试、Bug 跟踪与验收。
- **部署**：Docker Compose 一键环境（PG + Redis + MinIO）、Nginx 与域名/内网穿透配置、部署文档。
- **数据**：种子数据与演示账号脚本，保证答辩现场有内容可看。
- **交付**：四个附件表格、实验报告统稿排版、PPT 与演示脚本、现场录屏兜底。
- **验收**：一键部署可运行；演示数据齐全；四个附件与报告按模板齐备；答辩流程彩排通过。
- **依赖**：全部模块；不改业务代码，只提 Issue。

## 4. 工作流程

1. **开工前（今晚 – D1）**
   收口提案第 8 节的 5 个待确认议题（项目名与主题、评论敏感词策略、本地还是云库、大模型服务商与额度、最终分工确认）。分工已定，写入 `docs/ownership.md` 登记「包 + 目录」，写作用域不重叠。

2. **契约先行（D1 – D3，包 1 主笔）**
   冻结统一响应体、错误码号段、Token 约定、分页结构、Flyway V1 基线、Knife4j 可访问。全员评审通过后，任何契约变更必须走 PR 并通知相关包。

3. **依赖顺序**
   包 1 → 包 2 → 包 3 / 包 4 / 包 5 → 包 7；包 6 的后台框架必须在 D5 前给出骨架，包 6 与包 7 的页面才能接入。被依赖方延期时，依赖方先用 mock 数据占位，不空等。

4. **日常节奏**
   每天 15 分钟站会（昨天做了什么 / 今天做什么 / 卡在哪）→ 开发 → 自测 → 提 PR 到 `dev` → 相邻包 review → 合并；每周五下午在 `dev` 部署一次做集成演示。

5. **数据规则**
   每包只写自己模块的表；Flyway 脚本版本号按日期递增；禁止手改共享库，禁止修改别人已合入的脚本；种子数据统一由包 8 维护。

6. **文档与测试**
   每周补自己章节；D18 交章节初稿 + 本模块测试用例；包 8 统稿并汇总四个附件；报告按「需求—设计—实现—测试—总结」分工撰写。

7. **阻塞处理**
   接口以 Knife4j 在线文档为唯一依据；前端可先用 mock。任一包被阻塞超过 1 天，在群里挂「阻塞牌」，由相关包当天响应。

8. **里程碑评审**
   D5 / D12 / D18 各一次，全员参加；不达标当场定补救人与补救时间。

### 4.1 验收标准（Definition of Done）
